# ASCII 实时预览开关设计

## 目标

将当前 Inspector 顶部的“启用”复选框替换为一个放在“配色方案”下方的 ASCII 风格开关按钮。用户导入视频、调整参数后，主动开启或关闭右侧的实时 ASCII 预览。

## 交互定义

1. 默认关闭 ASCII 效果。导入视频不会自动启动 ASCII GPU pass。
2. 参数区仍可在关闭状态下编辑；预设、密度、字形大小、对比度、边缘细节和配色方案保持原有含义。
3. 参数区末尾显示“实时 ASCII 预览”和一个整块可点击的矩形开关按钮。
4. 关闭态为低亮深色，显示 `OFF`；开启态为暖金/荧光绿高亮，显示 `ON`。滑块位置、文字和色彩共同表达状态，不能仅依赖颜色。
5. 点击开启后，右侧立即重绘当前帧为 ASCII 效果；播放时持续实时更新。点击关闭后，右侧立即回到未字符化的合成预览。
6. 没有视频、渲染管线未就绪或当前仅有 Canvas2D 降级后端时，开关禁用，并提供具体原因。

## 视觉方向

开关采用低圆角、矩形、等宽字符与细网格描边，不强制模仿机械拨杆。开启态用现有界面的暖金色作为主信号，辅以极轻微的字符扫描或亮度过渡；关闭态保持深色、低对比。支持键盘操作，使用 `aria-pressed` 和包含当前状态的无障碍名称。

## 渲染链路

`AsciiInspector` 维护并显示参数；`App` 将开关状态与参数一起通过已有 `set-ascii-effect` 命令发给 worker；worker 更新 `PreviewRenderer` 的 ASCII 参数后，调用现有 `playback.refresh()`。该刷新在暂停时解码并绘制当前帧，在播放时由下一帧自然接管，因此点击不会要求用户额外播放、拖动或逐帧操作。

ASCII pass 保持在 GPU 合成后的输出转换前执行。启动前必须修复 `ascii.wgsl` 的向量 `clamp` 参数类型错误，否则所有 UI 状态都正确时仍无法产生有效的 GPU 命令。

## 边界

- 本功能是实时预览控制，不引入整段视频预转码、缓存进度或新的媒体文件。
- 本次不设计新的“导出 ASCII 视频”产品入口；导出行为需在后续独立需求中明确。
- 当前工作区存在与该需求无关的本地类型检查错误（Timeline 的 locale 属性与 Toolbar 浏览器测试夹具）。实施前必须先确认这些改动的归属，避免将它们误纳入本功能提交。

## 验收标准

- 导入后但未开启时，右侧能显示正常合成预览且没有 ASCII GPU pass。
- 点击开启/关闭时，暂停画面的右侧在一次操作后立即切换。
- 播放时，开启态持续渲染 ASCII；关闭态不运行 ASCII pass。
- Core WebGPU 与兼容 WebGPU 后端可用；Canvas2D 降级后端给出禁用说明。
- GPU shader 可在真实 Chromium WebGPU 环境编译；相关单元、浏览器和类型检查验证通过，或清楚记录既有无关阻塞项。
