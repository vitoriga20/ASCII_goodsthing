# LocalCut ASCII Studio 设计说明

## 目标

在 `vedio2ASCII/ascii-studio` 建立一个以 LocalCut 为代码底座的本地浏览器视频工作台。用户导入自己的视频后，在同一工作台中剪辑、实时预览 ASCII 效果、调整参数，并导出带可选独立音频的成片。原始参考仓库 `参考/localcut-main` 和现有 `vedio2ASCII` 临时导出工具均保留不动。

本轮先完成「可用工作台 + 实时 ASCII 转换 + 参数与时间线、导出打通」；不制作参考图中的人物粒子消散转场。

## 采用方案

采用 LocalCut 的 SolidJS、Mediabunny、WebCodecs、WebGPU、Worker 与 SharedArrayBuffer 架构，不嵌入此前基于 Canvas 的 Asciify 演示。ASCII 渲染将作为 LocalCut 加速效果链中的一个 GPU 效果：预览和导出走同一处理链，避免预览好看而导出失真或无法完成的问题。

选择该方案的原因：

- LocalCut 已具备实际的媒体导入、轨道时间线、播放、剪辑和导出基础能力，不重复造轮子。
- GPU 路径保持每帧一次提交，不走 `getImageData` 等 CPU 像素回读，适合长视频和实时调参。
- 机器或浏览器没有完整能力时，应用仍显示工作台与清晰的受限模式说明；不会假装已启用 GPU 加速。

## 交付范围

### 工作台界面

界面以所给参考图的空间层级为目标，而不复制其人物、品牌与不可读的装饰文字：

- 深黑、墨绿和暖金的电影感桌面工作台；圆角应用壳、低饱和粒子环境、细边框与高对比技术读数。
- 顶部：项目名、导入、能力状态、播放/撤销等常用操作和导出入口。
- 中部：左侧原始视频预览，右侧 ASCII 实时预览。两者使用同一时间轴，便于直接对照效果。
- 左侧：媒体导入、素材信息、基础预设和颜色/字符风格控制。
- 右侧：效果检查器，集中放置字符集、栅格密度、亮度/对比度、反相、色调、边缘增强、保留原色/单色等实际参数。
- 底部：真实可操作的 LocalCut 轨道时间线、缩略图、播放头、缩放、基本剪切/分割/修剪、播放控制和当前时间码。

屏幕优先按 1600×900 桌面尺寸还原，窄至 900px 时重排为单栏可用布局。可交互控件都支持键盘焦点和可读标签。

### 媒体与时间线

- 用户通过文件选择或拖拽导入本地视频；媒体内容不上传。
- 支持视频轨剪切、分割、修剪、排序和时间线播放。
- 支持额外选择独立 MP3/WAV 音频作为配音或原声替换，用于「视频文件本身无音轨」的场景。
- 显示视频分辨率、帧率、时长、音频存在性和当前性能档位。

### ASCII 效果

- 在 LocalCut GPU effect chain 中增加 `ascii` 效果与对应 WGSL 着色器。
- 每帧将源亮度映射到字形图集中的字符；栅格尺寸与输出分辨率保持正确纵横比，避免文字被拉伸。
- 第一轮可调参数：字符集/预设、字符密度、字符大小、亮度、对比度、阈值、反相、边缘增强、单色墨绿/暖金/保留原色视频三种模式。
- 预设至少包含：`Matrix Green`、`Gold Dust`、`Classic Mono`、`High Detail`。
- 效果参数写入项目状态；播放、暂停、时间线拖拽和导出都读取同一套参数。

### 导出与反馈

- 通过 LocalCut 现有管线导出，而不是等待浏览器的下载事件，因此不会再出现 30 秒 `waitForEvent('download')` 超时类问题。
- 导出面板可选格式/编码、分辨率、帧率、质量或速度、整段或时间范围；显示编码进度、已处理帧、预计剩余时间和失败原因。
- 输出应有有效时长、稳定帧率与可播放的容器元数据。视频没有内置音频时，若用户选了外置音频，导出合成该音频；未选择时会明确标注“无音轨”。

## 技术边界与数据流

1. 主线程 SolidJS 只渲染控制界面、读取低频状态和发送命令；不执行持续性逐帧处理。
2. Pipeline Worker 管理解码、时间线、ASCII GPU 着色、预览画布和导出；每一帧的颜色处理、ASCII 转换与合成在一个 GPU command encoder 中完成、一次提交。
3. 视频帧通过 `importExternalTexture` 每帧重新导入；预览和导出复用处理后的 GPU 纹理；所有 `VideoFrame` 明确关闭。
4. 采用 LocalCut 的 `BlobSource` 延迟读取本地文件；不全量读入内存。
5. WebGPU、WebCodecs、SharedArrayBuffer 或跨域隔离不完整时显示「受限模式」和恢复说明；不把 CPU Canvas 回读偷偷混进加速路径。
6. GPU 可用性为浏览器能力而非强制开关：支持 WebGPU 的 Chromium 会使用硬件适配器；驱动或浏览器不支持时以清晰状态提示处理。

## 目录与改造方式

- 新项目根目录：`vedio2ASCII/ascii-studio`。
- 将以 `参考/localcut-main` 为可追溯的上游基线复制到该目录后改造，不直接修改参考仓库。
- `vedio2ASCII` 下现有 `webm.html`、导出脚本和历史产物保留，便于追溯之前问题；新正式界面不依赖这些临时脚本。
- 新增 ASCII 相关逻辑放在 LocalCut 既有边界中：GPU/Worker 放 `src/engine/`，共享消息与项目状态放 `src/protocol.ts` 与对应模型，Solid 组件放 `src/ui/`，样式令牌放 `src/global.css`。

## 验收标准

1. 本地启动后直接出现完成态工作台，而非空白上传页；用户导入视频即可在左右预览区同步看到原画与 ASCII 效果。
2. 更改任一 ASCII 参数或预设时，右侧预览在播放/暂停状态均会即时更新。
3. 时间线的播放、暂停、跳转、裁剪和分割会同步更新两侧画面与时间码。
4. 支持外置 MP3/WAV；导出时不会将“源视频没有内置音频”误报为故障。
5. 导出的视频具有正常可检测的时长，音频选择存在时可播放音轨，且不依赖自动化脚本的下载事件超时。
6. 在完整 Chromium 能力下状态栏明确显示加速层级；在能力不足时给出明确限制与可行动说明。
7. 新的纯逻辑（ASCII 参数归一化、字符映射、导出音频策略、协议消息）有 Vitest 覆盖；现有 LocalCut 测试不减少，并通过 `pnpm` 的格式、类型、测试和构建检查。

## 非目标

- 不复制截图中人物素材、品牌标志、不可读文本或生成图中的粒子消散动画。
- 不增加云端上传、账户、远端编码、协作或素材库。
- 不承诺手机端专业剪辑，也不承诺无 WebGPU 的浏览器拥有相同性能。
