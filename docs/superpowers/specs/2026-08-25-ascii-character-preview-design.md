# ASCII 字符预览与方块拉杆设计

## 已确认的决策

- 右侧“ASCII 效果”显示可辨认的字符画，不再使用中心线、对角线和圆环组成的抽象纹理。
- 控制位于 Inspector 的“配色方案”下方；左侧文字固定为“实时渲染”，右侧是无文字的横向方块拉杆。
- 关闭时方块在左端，使用深灰轨道与冷灰滑块；开启时方块在右端，使用金黄滑块、暗金轨道和轻微辉光。
- 控制中不显示开启、关闭、ON 或 OFF。按钮用 aria-pressed 提供可访问状态。
- 不增加常驻进度条或状态行。只有命令超过 350 ms 尚未被 worker 确认时，才在右侧预览中央暂时显示“正在生成 ASCII 帧…”，收到确认立即消失。

## 字符渲染

ASCII pass 保持在现有 WebGPU 合成后的输出路径。每个画面单元先按亮度映射到 8 个密度等级，再以 5×7 位图字形输出空格、点、冒号、星号、加号、井号、百分号和 @。高亮级也绘制 @ 字形，不能再返回整格填充；因此亮部仍保留字符留白和轮廓。

密度、字形大小、亮度、对比度、边缘细节和配色方案继续复用现有 AsciiEffectParams。颜色模式只改变字符墨色；原色视频模式以采样色乘以字形遮罩。

## 交互与反馈

1. 导入视频时默认关闭 ASCII。
2. 点击方块拉杆后，App 发送既有 set-ascii-effect 命令。
3. worker 写入 PreviewRenderer、刷新暂停帧，并回传一次“命令已应用”确认。
4. 播放时下一帧自然使用新参数；暂停时刷新当前帧。UI 不创建第二条播放循环。
5. 若 worker 没有在 350 ms 内确认，右侧 ASCII 监视器显示临时等待覆盖层；确认后立即隐藏。该提示不是整段视频的转换进度。

## 验收标准

- 开启后右侧每一个明暗等级都能看到离散字符；亮部不得是整格色块。
- 拉杆外形与已确认参考一致：矩形槽、方形滑块、左关右开。
- 页面常态只出现“实时渲染”和拉杆；不会出现当前的“标题 + 小按钮”布局。
- 暂停帧切换后立即重绘；播放时持续更新；无 WGSL、WebGPU pipeline 或命令缓冲错误。
- 只有命令迟迟未被 worker 确认时才显示临时反馈，不显示常驻进度条。
