# Asciify 视频 ASCII 导出设计

## 目标

使用 `参考/asciify-main` 中的 Asciify 渲染器，将 `音视频` 目录中的指定 MP4 转换为 ASCII 风格的 MP4，并保留同目录配套 MP3 的声音。

输入视频为 852×480、24 fps、约 212 秒。输出文件位于 `音视频` 目录，文件名在原视频名后追加 `_ascii.mp4`。原始 MP4 与 MP3 不会被修改。

## 方案选择

采用“浏览器渲染 + FFmpeg 合成”方案：浏览器页面使用 Asciify 的 WebGL 渲染器按视频帧生成 ASCII 画面，并录制无声视频；FFmpeg 使用配套 MP3 作为音源，将二者编码为兼容性良好的 H.264/AAC MP4。

纯浏览器录制通常只能可靠得到 WebM，且音轨支持依浏览器而变；命令行 ASCII 转换器则不能满足使用 Asciify 的范围，因此不采用。

## 组件与数据流

1. `demo/video` 提供本地视频选择、预览画布、开始导出按钮、进度和错误提示。
2. 页面通过 `HTMLVideoElement` 解码视频；每个可用视频帧调用 `asciify.rasterizeImage(video)`，输出到 Canvas。
3. `MediaRecorder` 捕获 Canvas 流，输出临时无声 WebM。帧率固定为源视频的 24 fps。
4. 本地导出脚本驱动页面加载指定 MP4，取得临时 WebM，并调用 FFmpeg 与同目录配套 `_audio.mp3` 合成最终的 `_ascii.mp4`。
5. 合成完成后验证输出文件存在且同时包含 H.264 视频流与 AAC 音频流。

## 输出与质量边界

- 渲染尺寸固定为源视频 852×480，避免不必要的放大与文件膨胀。
- 首选 WebGL；设备不支持时由 Asciify 自动回退到 Canvas 2D。
- 使用 Asciify 默认字符映射与深色背景，保留其 GUI 参数，便于后续手动调整字符大小、对比度和颜色。
- 最终 MP4 使用 H.264 视频和 AAC 音频；音频从配套 MP3 读取。

## 错误处理

- 未选择视频、视频解码失败、浏览器不支持 `MediaRecorder`、渲染初始化失败和 FFmpeg 合成失败均显示明确提示并停止导出。
- 缺少配套 MP3 时不生成静音的“保留音频”文件，而是明确报错。
- 不覆盖已有输出；若目标文件存在，导出器生成带时间戳的替代文件名。

## 验证策略

先为可独立测试的导出命名与配套音频匹配逻辑编写失败测试，再实现最小逻辑并验证通过。随后执行类型检查与现有测试，并对最终 MP4 用 FFprobe 验证：文件存在、分辨率为 852×480、帧率为 24 fps，且包含 H.264 视频与 AAC 音频流。
